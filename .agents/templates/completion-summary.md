# Completion Summary Visual Template

복잡한 소스코드 작업 또는 Plan 문서 작업이 완료된 뒤 대화에 표시하는 요약 인포그래픽의 구성 기준이다.
이 템플릿은 프로젝트 파일이나 Git에 이미지 asset을 추가하라는 지시가 아니다.

## 생성 조건

아래 중 하나에 해당할 때만 생성한다.

- 여러 구성 요소, 상태 전이, 비동기 처리, 외부 Provider, 보안 경계를 다루는 소스코드 구현·변경
- 구현 순서, 구성 요소 관계, 상태 전이, API 계약을 새로 정의하거나 크게 바꾸는 Plan 문서 작성·갱신

단순 문서·지침·템플릿 수정, 포맷 변경, 리네임, 작은 설정 변경, 커밋·푸시만 수행한 작업에는 생성하지 않는다.
복잡한 작업이라도 관계를 텍스트 한두 문장으로 충분히 설명할 수 있으면 텍스트 요약을 우선할 수 있다.

## 생성 전 확인

- 변경 파일, 검증 명령과 결과, commit hash, push 상태를 실제 결과로 확인한다.
- 실패·미완료·보류 상태를 완료처럼 표현하지 않는다.
- Token, secret, authorization header, 실제 내부 IP, 개인 경로, 민감 command를 제외한다.

## 권장 구성

작업 성격에 맞는 항목만 골라 4개 안팎의 짧은 섹션으로 구성한다.

```text
제목: 작업명 + 완료 상태
결정 배경: 해결하려던 문제 또는 목표
주요 변경: 핵심 설계·구현·문서 변경 2~6개
반영 결과: 파일·검증·commit/push 결과
다음 작업: 가장 가까운 후속 단계 하나
```

- 소스코드 작업은 구성 요소 간 동작 흐름 또는 상태 변화를 시각화한다.
- Plan 작업은 목표에서 구현 단계로 이어지는 관계를 시각화한다.

## 표현 규칙

- 한국어 중심의 읽기 쉬운 인포그래픽으로 만들고, 숫자·파일명·commit hash는 원문 그대로 표기한다.
- 실제 결과만 사용한다. 계획, 추측, 아직 수행하지 않은 Git 작업에는 `예정` 또는 `미수행`을 명확히 표시한다.
- 상세 작업에는 결정 배경·주요 변경·반영 결과·다음 작업을 포함한다.
- 이미지는 인라인 preview로 제공하며, 사용자가 명시적으로 요청하지 않는 한 저장·커밋하지 않는다.
- 이미지 생성이 불가능하면 같은 구성의 monospace 텍스트 카드로 대체한다.
