# Template Usage and Maintenance

템플릿은 반복되는 설계·검토에서 중요한 항목을 빠뜨리지 않기 위한 시작점이다. 템플릿 자체가
프로젝트의 현재 정책을 대체하지 않으며, 항상 `AGENTS.md`와 관련 아키텍처·보안·API 계약 문서를 우선한다.

## 사용 시점

### `feature-plan.md`

아래 중 하나에 해당하는 기능을 구현하기 전에 작성한다.

- 새 Agent Provider adapter 또는 Provider capability 추가
- 새 REST endpoint 또는 WebSocket 이벤트 추가
- Session, Run, Approval 등 상태 전이 변경
- 인증·권한·승인 흐름 변경
- 모바일 API, Gateway, Provider runtime, Workspace 중 둘 이상에 영향을 주는 기능

작은 버그 수정, 오탈자 수정, 한 모듈 내부의 호환 가능한 리팩터링에는 작성하지 않아도 된다.

완성한 계획은 필요할 때 이 디렉터리에 저장하지 말고, 해당 issue/PR 설명 또는 추적 가능한
프로젝트 문서에 남긴다. 반복 사용 가능한 빈 양식만 이 디렉터리에 둔다.

### `api-change.md`

외부 REST endpoint 또는 WebSocket 이벤트를 추가·변경·제거할 때 사용한다. 체크 항목은
PR 설명 또는 기능 계획에 반영한다. Provider 내부 프로토콜만 바뀌고 외부 계약과 capability가
변하지 않으면 사용할 필요가 없다.

## 템플릿 갱신 시점

다음 중 하나가 발생하면 템플릿을 갱신한다.

- 두 번 이상 반복된 작업에서 같은 검토 항목이 빠졌거나, 새 항목이 반복해서 필요해졌다.
- 공통 개발 절차, 보안 원칙, API 호환성 기준이 바뀌었다.
- 새로운 Provider 유형 또는 반복 가능한 작업 흐름이 추가됐다.
- 회고·장애 분석에서 계획 또는 API 검토 단계의 누락이 원인으로 확인됐다.

특정 기능만의 입력값, Provider 전용 세부 동작, 일회성 해결 방법은 템플릿에 넣지 않는다.
그런 내용은 기능 계획, Provider adapter 문서 또는 ADR에 기록한다.

## 갱신 방법

1. 왜 기존 템플릿이 부족했는지와 영향을 받는 반복 작업을 설명한다.
2. 최소한의 공통 질문 또는 체크 항목만 추가한다.
3. `AGENTS.md` 및 관련 정책 문서와 모순되지 않는지 확인한다.
4. 이미 작성된 과거 계획을 소급해 수정하지 않는다. 새 작업부터 사용한다.
